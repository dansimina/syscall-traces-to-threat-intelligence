=== INSTRUCTIONS ===

Produce a comprehensive, professional analysis report in JSON format. This report will be formatted for executive and technical audiences.

CRITICAL RULES FOR VERDICT AND SEVERITY:
- If the sample is a normal system command (find, ls, grep, cat, df, top, ps, etc.) performing its expected function with no network C2, no persistence, no file encryption, and no data exfiltration, the verdict MUST be "benign" and severity MUST be 0.
- Normal file reads, directory listings, and system discovery by standard tools are NOT malicious. Do not assign MITRE ATT&CK techniques to normal tool behavior.
- Educational/proof-of-concept malware running against localhost (127.0.0.1) with simulated C2 but NO destructive payload should score 7-8. If it actually encrypts/deletes files or exfiltrates data (even in sandbox), score 8-9 — the destructive capability is proven.
- Reserve severity 10 for real-world-ready malware with external C2, confirmed destructive payload, and no obvious educational markers.
- DATA EXFILTRATION always scores >= 7, even when small amounts of data are sent and even when the destination is localhost. Reading sensitive material (credentials, keys, /proc/net/, /etc/shadow) and transmitting it over any network socket is inherently malicious. Score higher (8-9) when the destination is a non-loopback IP, data volume is large, or the channel uses encoding/obfuscation (base64 payloads, DNS subdomains, HTTP query strings).

Requirements:
1. CLASSIFICATION: "malicious", "suspicious", or "benign" — this is a strict machine-readable label used for computing precision/recall metrics. It must always be exactly one of these three lowercase strings.
2. VERDICT: same value as classification. This field is displayed in the report header.
3. SEVERITY: 0-10 scale:
   - 0: Benign — normal program behavior, no security concern
   - 1-3: Low — minor anomalies, could be legitimate
   - 4-6: Medium — suspicious patterns, limited evidence of malicious intent
   - 7-8: High — active exploitation, data theft, persistence, C2, exfiltration
   - 9: Very High — multi-stage attack with significant impact or confirmed exfiltration to external C2
   - 10: Critical — confirmed destructive payload with real-world impact
4. EXECUTIVE SUMMARY: 2-3 paragraphs for non-technical leadership. If benign, briefly state what the program does and that no threat was found. Include: what was observed, what is the risk (if any), what to do about it.
5. KILL CHAIN: Map the attack flow ONLY if the verdict is suspicious or malicious. For benign samples, describe the normal execution flow instead.
6. MITRE ATT&CK: Only include techniques for genuinely malicious actions. Do not map benign behavior to attack techniques.
7. EXFILTRATION CHECK: Before finalizing the verdict, explicitly verify: did the process read any sensitive file AND establish any network connection? If yes, this is at minimum SUSPICIOUS (T1041). Check io_burst/write_burst total_bytes on socket FDs, HTTP query-string content in network writes, and the network_data_exfil / dns_exfiltration patterns in the heuristic patterns section.
8. IOCs: Only for suspicious or malicious verdicts. Empty for benign.
9. TIMELINE: Key events in chronological order with timestamps.
10. EVIDENCE GAPS: What couldn't we observe?
11. RECOMMENDATIONS: Only for suspicious or malicious verdicts. For benign samples, state that no action is required.
