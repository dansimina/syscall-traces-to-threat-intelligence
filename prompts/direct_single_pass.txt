Analyze the raw events below and produce a comprehensive, professional analysis report in JSON format. You must perform BOTH the low-level behavioral analysis (identifying actions, kill chain phases, IOCs) AND the high-level intelligence synthesis in a single pass.

CRITICAL RULES FOR VERDICT AND SEVERITY:
- If the sample is a normal system command (find, ls, grep, cat, df, top, ps, etc.) performing its expected function with no network C2, no persistence, no file encryption, and no data exfiltration, the verdict MUST be "benign" and severity MUST be 0.
- Normal file reads, directory listings, and system discovery by standard tools are NOT malicious. Do not assign MITRE ATT&CK techniques to normal tool behavior.
- Educational/proof-of-concept malware running against localhost (127.0.0.1) with simulated C2 but NO destructive payload should score 7-8. If it actually encrypts/deletes files or exfiltrates data (even in sandbox), score 8-9 — the destructive capability is proven.
- Reserve severity 10 for real-world-ready malware with external C2, confirmed destructive payload, and no obvious educational markers.
- DATA EXFILTRATION always scores >= 7, even when small amounts of data are sent and even when the destination is localhost. Reading sensitive material (credentials, keys, /proc/net/, /etc/shadow) and transmitting it over any network socket is inherently malicious. Score higher (8-9) when the destination is a non-loopback IP, data volume is large, or the channel uses encoding/obfuscation (base64 payloads, DNS subdomains, HTTP query strings).

Requirements:
1. CLASSIFICATION: "malicious", "suspicious", or "benign"
2. VERDICT: same value as classification
3. SEVERITY: 0-10 scale calibrated per the system instructions
4. EXECUTIVE SUMMARY: 2-3 paragraphs for non-technical leadership
5. KILL CHAIN: Map the attack flow ONLY if suspicious or malicious
6. MITRE ATT&CK: Only for genuinely malicious actions
7. EXFILTRATION CHECK: Before finalizing the verdict, explicitly verify: did the process read any sensitive file AND establish any network connection? If yes, this is at minimum SUSPICIOUS (T1041). Check io_burst/write_burst total_bytes on socket FDs and HTTP query-string content in network writes.
8. IOCs: Only for suspicious or malicious verdicts
9. TIMELINE: Key events in chronological order with timestamps
10. EVIDENCE GAPS: What couldn't we observe?
11. RECOMMENDATIONS: Only for suspicious or malicious verdicts
